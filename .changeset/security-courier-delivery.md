Delivery tracking actually works, and delivery webhooks fail closed (BREAKING). (1) H7: the send path never persisted the provider's message id, so every delivered/opened/clicked/bounced webhook UPDATE matched zero rows — tracking was silently dead. `ICourierChannel.send` may now return `{ providerMessageId }` (returning `void` is still valid); the email channel returns Resend's `id` and SMTP's `Message-ID` (brackets stripped to match provider events), and the dispatcher persists it before marking the message sent. (2) H8: delivery webhook routes previously processed **unverified** payloads when no signing key was configured — anyone who found the URL could forge delivery/bounce events. A provider's route is now only registered when its key is set, and the handlers 401 without one. The SendGrid check also used HMAC where SendGrid actually signs with **ECDSA** — genuine events could never verify; it now performs real ECDSA (P-256) verification against the base64 "Verification Key" from the SendGrid dashboard (`delivery.signingKeys.sendgrid` semantics changed from HMAC secret to that public key). Mailtrap has no signature scheme at all, so its route requires the explicit `delivery.allowUnverifiedMailtrap: true` dev/test opt-in.
